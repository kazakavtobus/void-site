# VOID → Yandex Cloud Object Storage

## Почему Object Storage

У VOID статический HTML/CSS/JS-сайт. Для первой версии не нужны VM, Docker, база данных или API. Object Storage хранит файлы `dist/` и предоставляет режим статического сайта. **Это не хостинг серверной формы**: её подключим позже отдельным сервисом, при необходимости.

Официальная документация:
- https://yandex.cloud/ru/docs/storage/operations/hosting/setup
- https://yandex.cloud/ru/docs/storage/tutorials/static/
- https://yandex.cloud/ru/docs/storage/tutorials/cdn-hosting/console

## 1. Создать бакет

В своём Yandex Cloud → Object Storage создайте бакет с глобально уникальным именем (например, `void-site-prod-...`). Определите имя **до** настройки GitHub Secret `YC_BUCKET`.

В настройках бакета:
- разрешите публичное чтение объектов и списка объектов согласно требованиям статического хостинга Yandex Cloud;
- вкладка **Веб-сайт** → режим **Хостинг**;
- главная страница: `index.html`;
- страница ошибки: `404.html`.

Предварительный адрес сайта можно получить в настройках веб-сайта бакета. До настройки HTTPS/домена он подходит лишь для проверки.

## 2. Подготовить доступ на запись

Создайте отдельный сервисный аккаунт только для деплоя этого сайта и выдайте ему **минимальные права на запись/удаление объектов в нужном бакете**, соответствующие используемому `aws s3 sync --delete` (не пользуйтесь мастер-ключами личного аккаунта). Создайте статическую пару ключей для Object Storage.

Ключи **не присылайте в чат, не храните в коде и не сохраняйте в файлах репозитория**.

## 3. Один раз добавить GitHub Actions Secrets

Репозиторий GitHub → Settings → Secrets and variables → Actions → New repository secret:

| Имя | Значение |
| --- | --- |
| `YC_BUCKET` | имя Object Storage бакета |
| `YC_S3_ACCESS_KEY_ID` | идентификатор статического ключа сервисного аккаунта |
| `YC_S3_SECRET_ACCESS_KEY` | секретный ключ сервисного аккаунта |

Можно включить защиту окружения `production` в Settings → Environments → production, чтобы требовалось ручное подтверждение публикации.

## 4. Публикация

Откройте `Actions → VOID — публикация в Yandex Cloud → Run workflow`, включите чекбокс подтверждения и запустите.

Workflow **каждый раз заново** запускает тесты, сборку и smoke-test, а затем синхронизирует `dist/` с бакетом через S3-совместимый endpoint `https://storage.yandexcloud.net`.

**Осторожно:** шаг использует `--delete` для удаления из бакета файлов, которых больше нет в `dist`. Поэтому бакет должен быть выделен **только под этот сайт** и не содержать других данных. До первой публикации проверьте имя `YC_BUCKET`.

При отсутствии любого секрета публикация завершится ошибкой без попытки загрузки. Успешный GitHub Actions run ещё не гарантирует корректность публичного URL — проверьте адрес сайта и 404 лично.

## 5. Домен и HTTPS (после первой загрузки)

Object Storage может показать технический адрес сайта, но для основного пользовательского домена нужно настроить DNS, сертификат и HTTPS по поддерживаемой схеме Yandex Cloud (например, Certificate Manager и CDN). **Не считайте выпуск завершённым при доступности только по HTTP.**

После назначения домена откройте `content/site.json`, установите `siteUrl` в HTTPS URL уровня корня, завершающийся `/`, например `https://void.example/`, и пересоберите сайт. Тогда появятся корректный canonical и sitemap; до этого `robots.txt` запрещает индексирование.

## 6. Проверка после релиза

Проверьте главную `/`, `/cases/`, `/privacy/`, CSS/JS, мобильную навигацию, страницу несуществующего адреса (404), код ответа HTTP, HTTPS, email CTA. Отдельно проверьте доступность сайта с российских сетей.

## Важно

Статический хостинг **не выполняет серверный JS**: API приёма заявок, если он понадобится, нужно разворачивать отдельно. Ни хостинг, ни CMS, ни платную инфраструктуру до этого этапа усложнять не требуется.
