# VOID — сайт-портфолио

Версия **0.3.0** · светлый минималистичный сайт-портфолио веб-дизайнера.

Содержимое: главная страница, услуги, информация об авторе, контакты через email, список авторских концептов и детальные страницы **только опубликованных** кейсов. Все кейсы пока не завершены и честно отмечены своими статусами.

## Быстрый запуск

Установите Node.js **22 или новее**. Внешних npm-зависимостей нет: `npm install` не требуется.

```bash
npm run check      # 8 тестов + сборка + проверка ссылок/файлов
npm run preview    # откройте http://127.0.0.1:4173
```

Окончательные файлы сайта появляются в `dist/`. Не редактируйте их вручную: изменения вносятся в исходники и пересобираются.

## GitHub

Исходники проекта хранятся в репозитории **[kazakavtobus/void-site](https://github.com/kazakavtobus/void-site)** (ветка `main`). Каждое обновление запускает GitHub Actions с тестированием и сборкой. Папка `dist/` создаётся автоматически и не хранится в Git.

При необходимости локальной работы:

```bash
git clone https://github.com/kazakavtobus/void-site.git
cd void-site
npm run check
npm run preview
```

Подробнее: [docs/GITHUB.md](docs/GITHUB.md).

## Где публикуем

**Yandex Cloud Object Storage** — вместо GitHub Pages. Разовый деплой через Actions **VOID — публикация в Yandex Cloud** уже подготовлен, но **не начнётся**, пока вы не создадите бакет, не настроите доступ и не запустите его вручную с подтверждением. Секреты никогда не помещаем в репозиторий.

## Кейсы

Статусы проектов в `content/projects.json`:

- `planned` — только анонс;
- `draft` — в разработке, без опубликованной страницы;
- `published` — страница будет создана при наличии содержательных `sections`.

На данный момент СЕЧЕНИЕ, ПОРОГ и ПОЛУТОН — вымышленные авторские концепты, ни один не опубликован как законченная работа. Не заменяйте статусы до проверки фактической реализации кейса.

## Важные ограничения перед запуском

- Адрес `work@danilkazakov.ru` взят из доступного GitHub-профиля, требует подтверждения владельца.
- Пока **нет серверной формы**: кнопка открывает письмо, которое посетитель самостоятельно отправляет из почтового приложения. Возможна ситуация, когда почтовый клиент не установлен.
- Аналитика и CRM **не подключены**. UTM-метки локально добавляются в черновик письма, если они есть.
- `content/site.json` → `siteUrl` сейчас пуст. Поэтому сборка создаёт `robots.txt` с `Disallow: /`. **Перед публичным SEO-запуском** впишите HTTPS-домен с конечным `/` (например `https://site.ru/`), затем появятся `sitemap.xml` и canonical.
- HTTPS для своего домена нужно настроить отдельно в Yandex Cloud с подходящим сертификатом и способом маршрутизации.
- Не утверждайте, что GitHub Actions или публикация в Yandex Cloud прошли, пока не увидите успешный запуск и работающий публичный URL.
